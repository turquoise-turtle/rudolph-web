A rule with the CEL policy matches a binary like any other rule, by its binary hash, certificate, team ID, signing ID or CDHash, and then decides with a CEL expression each time the binary runs. Santa evaluates it on the Mac, with the execution's arguments, environment and user, so one rule can allow a tool for most uses and block one of them.

Rudolph talks to Santa with sync protocol v1, so Santa evaluates its CEL rules with CEL v1. The web view checks an expression the same way before saving it: an expression Santa could not compile is refused, as Santa would skip the rule on every Mac.

What an expression can use

NameTypeWhat it is
target.signing_idstringThe binary's signing ID as a rule has it, such as EQHXZ8M8AV:com.google.Chrome or platform:com.apple.profiles.
target.team_idstringThe team ID it is signed with; empty for platform binaries and unsigned ones.
target.is_platform_binaryboolWhether it is part of macOS.
target.signing_timetimestampWhen it was signed, by the signer's own clock. Test with has(target.signing_time) first: a binary may not have one.
target.secure_signing_timetimestampWhen Apple's timestamp server says it was signed, which the signer cannot change. Test with has(target.secure_signing_time) first.
argslist of stringsThe arguments, starting with the command as it was run (args[0]).
envsmap of stringsThe environment variables. envs['NAME'] is an error when NAME is not set, so test 'NAME' in envs first.
euidintThe effective user ID: 0 is root, as with sudo.
cwdstringThe working directory.
pathstringThe path of the binary being run.

The expression returns true to allow (as ALLOWLIST) or false to block (as BLOCKLIST), or one of the policies {{range $i, $p := .Policies}}{{if $i}}, {{end}}{{$p}}{{end}}, usually as condition ? BLOCKLIST : ALLOWLIST. It has CEL's standard functions and macros (such as startsWith, endsWith, contains, matches, size, in, exists, all and timestamp) and the string functions charAt, format, indexOf, join, lastIndexOf, lowerAscii, replace, reverse, split, substring, trim and upperAscii. An expression that fails while it runs, such as reading args[5] of a shorter command, decides nothing: Santa goes on to the binary's other rules and then its client mode, or blocks it on a Mac set to fail closed.

What needs Workshop

Workshop, North Pole Security's commercial sync server, sends rules with CEL v2, which adds ancestors (the processes that started this one), fds (its open file descriptors) and the FD_TYPE_ values, target.entitlements, the policies REQUIRE_TOUCHID, REQUIRE_TOUCHID_ONLY, SEATBELT and AUDIT, and the functions today(), now(), days(), weekdays(), policy_for_range(), kill_on_expiry(), require_touchid_with_cooldown_minutes() and require_touchid_only_with_cooldown_minutes(). Rules from Rudolph cannot use any of them, and an expression that does is refused.

Caching

Santa normally caches its decision for a binary until the binary or the rules change. When an expression reads only target, its answer is the same every time the binary runs, so Santa caches it. Once it reads args, envs, euid, cwd or path, Santa evaluates it again on every execution, which costs a little each time the binary runs: keep such rules to the binaries that need them.
